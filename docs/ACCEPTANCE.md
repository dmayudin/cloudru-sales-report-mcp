# Приёмка перед рекомендацией конечным пользователям

Статусы: PASS / FAIL / BLOCKED / NOT_RUN. Сохранять дату, commit, клиент и версию, окружение, безопасные IDs/суммы и доказательство каждого результата. Не записывать секреты. Этот файл — чек-лист, а не заявление, что проверки уже пройдены.

| Проверка | Критерий | Текущее доказательство |
|---|---|---|
| Пакет | Manifest/hash совпадают, секретов нет | Проверяется сборкой и аудитом публикации |
| Установка | Чистая установка, все references/runtime доступны, нет silent overwrite | Автоматические tests временных каталогов |
| Поведение после установки | Агент объясняет возможности и сразу продолжает onboarding | Нужен отдельный проход каждого клиента |
| Новый клиент | Понятная регистрация, личные подтверждения пользователя, нет секретов в чате | Инструкции готовы, пользовательский проход не выполнен |
| Существующий клиент | Выбран проект и проверены ограниченные права | Нужен live Cloud.ru |
| Secret handoff | Ввод скрыт, нет утечки в tool logs/chat/Git | Code review/tests не заменяют проверку конкретного клиента |
| Полная стоимость | Все категории, текущие тарифы, usage assumptions, согласие до apply | Unit tests калькулятора; реальная смета нужна |
| Bootstrap | VM, сеть/DNS, TLS и единственный state без дублей | Template validate; live apply не выполнен |
| Remote MCP | initialize/list/call, valid/invalid/expired token, Host/Origin | Нужен реальный удалённый тест |
| Импорт | Контрольный CSV даёт ожидаемые суммы | Unit/adapter tests; cloud e2e не выполнен |
| Повтор/ошибки | Нет удвоения, плохой CSV не заменяет текущую витрину | Частично tests; live повтор нужен |
| Managed BI API | Авторизация, driver, connection/dataset/chart/dashboard | BLOCKED до подтверждения supported headless credentials |
| BI verify | Совпали snapshot ID, rows, revenue, contribution | Нужен реальный BI |
| Пользовательская ссылка | Пользователь открыл BI и увидел нужные данные | NOT_RUN |
| Регулярность | Новый файл пришёл из источника, настоящий scheduled run, BI обновился | Source adapter tests; облачный timer NOT_RUN |
| Остановка | Понятно, какие расходы/данные остаются; подтверждён фактический исход | Lifecycle tool отсутствует; отдельная API-процедура |

## Клиентская матрица

Отдельно прогнать Codex, Claude Code и Hermes, если они входят в список поддерживаемых. Для каждого указать версию, способ установки, private input, remote MCP, токен, первый ответ, выполнение и блокировки. До таких результатов использовать формулировку «агент-независимый пакет», а не «проверено в любом агенте».

## Минимальные сценарии

1. Ссылка → установка → объяснение возможностей → три вопроса без ключей в чате.
2. Новый аккаунт → пользователь выполняет регистрацию → защищённый доступ → смета.
3. Существующий аккаунт + тестовые данные → созданное облако → рабочая BI-ссылка.
4. Тот же SHA повторно → те же итоги; другой полный SHA → новая активная витрина.
5. Неверный файл → предыдущий отчёт сохранён.
6. Источник S3 и согласованное расписание → scheduled run с новым SHA.
7. Нет нужного API в Managed BI → точная блокировка, без browser fallback или фиктивного успеха.
8. Пользователь просит «остановить» → уточняется timer/BI/вся среда, раскрываются остаточные расходы, нет автоматического удаления.

При FAIL/BLOCKED в mandatory cloud этапах выпуск остаётся preview. Исправления должны проверяться по реальному наблюдаемому результату, а не изменением текста навыка.
