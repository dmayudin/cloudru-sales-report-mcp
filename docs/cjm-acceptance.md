# CJM: поставка 0.2.0, 28.10.2026

## Реализовано и проверено без облачного запуска

- Skill без пользовательских абсолютных путей; установщик Python stdlib с явными директориями текущего агента, сохранением runtime_root и отказом перезаписать существующую установку.
- Установка не запускает локальный сервер. Пакет распространяется с инструкцией INSTALL.md и checksum manifest.
- Onboarding: три начальных вопроса; отдельные ветки нового/существующего клиента, личные действия пользователя, Key ID/Key Secret правильного типа, безопасный ввод, read-only проверка. Пользователь не выбирает сети, UUID и спецификации.
- Режимы: разовый, новые файлы по запросу, плановое получение полного снимка из приватного S3. Для прочих источников требуется реализованный коннектор, который не выдается за существующий.
- Новый MCP tool sales_refresh_source; worker --source использует то же ядро. Невалидный источник не публикуется. Произвольный URL и чужой bucket в аргументах не принимаются.
- Новый MCP tool sales_estimate_cost: 11 категорий расходов, VAT-inclusive ставки, usage assumptions, 30 дней/720 часов, дата/источник. Нет полной цены при неизвестном компоненте или тарифах старше 7 дней. Тарифы получает и проверяет агент/оператор, калькулятор сам их не загружает.
- Передача результата: проверенный URL, вход, период, свежесть данных, режим, полная месячная оценка и условия. Приостановка обновления и прекращение биллинга явно различаются.

42 unit/in-process теста прошли: расчёт/полнота/давность цен, invalid numbers, чтение source scope, отсутствие публикации повреждённого CSV, переносимая установка и защита от перезаписи, прежние проверки адаптеров и MCP tool contracts. Skills frontmatter проверяется отдельно. Локальный MCP listening server/БД не запускались.

## Честные границы готовности

- Архив подготовлен, но GitHub/другая публичная площадка ещё не выбрана и публикация не выполнена.
- Инсталлятор проверен в временных папках. Полный пользовательский проход отдельно в Codex/Claude Code/Hermes не выполнен; универсален файловый пакет и процесс, не гарантирован любой клиент.
- Общего hosted MCP, защищённой web-формы onboarding, многопользовательской изоляции и OAuth-подключения к Cloud.ru в поставке нет. Текущий runtime — отдельный single-tenant сервер клиента; терминал без эха — имеющийся механизм ввода, а не готовая web-форма.
- Автоматическая загрузка актуальных тарифов, IAM least-privilege policy generator, облачный lifecycle/delete tool и коннекторы Drive/1С/маркетплейсов не реализованы. Подготовку тарифов и точных прав выполняет агент по официальным источникам; без подтверждённой сметы/прав не создавать ресурсы.
- API-доступ Managed BI, настоящий remote MCP handshake, вход пользователя по ссылке и scheduled run требуют live-проверки после ввода ключей. Финальный сценарий нельзя считать готовым к массовой эксплуатации до неё.

## Пользовательские приёмочные задания

1. «Cloud.ru у меня нет. Есть файл продаж. Хочу один отчёт». Ожидается короткий первый разговор и ближайший шаг регистрации; никаких запросов пароля в чат и никакой платной инфраструктуры без сметы.
2. «Аккаунт есть, вот название проекта, ключ хочу вставить безопасно». Ожидается реальный private input/terminal handoff, а не фиктивная ссылка формы; затем API-проверка доступа.
3. «Обновляй ежедневно из Google Drive». Агент проверяет коннектор; при его отсутствии сообщает это и предлагает поддерживаемый маршрут, не обещает работающий Drive.
4. «Сколько стоит в месяц?» При неизвестной сети/источнике/agent usage итог не выдается; агент собирает недостающее. При полном документе показывает итог и предположения.
5. «Останови обновление». Агент объясняет сохранение расходов инфраструктуры; удаление данных не следует из остановки таймера.
6. «Дай рабочую ссылку». Требуются сверенные суммы и проверенный пользовательский доступ, не URL приватного hostname или успешный Terraform plan.
