# Стоимость, регулярность и результат

## Полная стоимость

` sales_estimate_cost(days=30) ` суммирует проверенные оператором тарифы из tariffs.json. Это расчёт, не API получения цен. Агент самостоятельно проверяет актуальные тарифы/льготы и заполняет серверный файл. При отсутствии хотя бы одной категории или устаревании данных total=null; известную часть нельзя назвать полной ценой.

Категории: ClickHouse, BI, VM MCP, её диск, сеть/IP/трафик, DNS, S3/операции, логи, домен/TLS, источник/коннектор и использование агента. Каждая имеет цену с НДС, единицу, количество, дату проверки, источник и предположение. Нулевую дополнительную цену обоснуй: например уже оплаченная подписка пользователя; не подменяй неизвестность нулём. Сумма может включать консервативную оценку переменных затрат, явно названную оценкой. Не обещай бесплатность BI без подтверждения eligibility.

По умолчанию месяц расчёта = 30 суток, 720 часов; укажи это рядом с суммой. Для помесячных услуг стоимость масштабируется пропорционально горизонту — это оценка, не правило выставления счёта. Для разового режима рассчитывай фактический согласованный срок доступности плюс покажи цену при сохранении на месяц.

Фраза: «При вашем объёме данных и обновлении [частота] — ориентировочно X ₽ за 30 дней с НДС. Включены [краткие основные составляющие]. Оценка предполагает [объём/режим]. [Подписка агента уже оплачена / дополнительная оценка]. Создать решение в этих пределах?»

В смете отдельной строкой покажи запасной вариант: платный Managed BI (3,7881 ₽/ч с НДС по тарифу 7.EVO.18 от 28.10.2026, около 2 727 ₽ за 30 дней), если бесплатный инстанс не создаётся или уже занят в организации. Пример полной сметы пилота 28.10.2026 (ClickHouse 2 vCPU/16 ГБ, VM 2 vCPU/4 ГБ, IP, диски; BI free tier): ≈279 ₽ в сутки, ≈1 952 ₽ за 7 дней, ≈8 365 ₽ за 30 дней; ClickHouse 4 vCPU/16 ГБ добавляет ≈72 ₽ в сутки. Реальные значения лежат в `deploy/tariffs.example.json` (verified_at), устаревшие пересчитай.

Кластер, зависший в статусе «Создается» без хостов, не удаляется через API; тарифицируется ли он, Cloud.ru в документации не говорит — укажи это как открытый вопрос и включи в обращение в поддержку.

Не своди смету только к ClickHouse. Отдельно укажи разовую настройку, если оператор берёт плату; не придумывай коммерческий тариф. Отсутствующий тариф shared MCP — неизвестная стоимость, а не бесплатный сервис. Оценка не является автоматическим ограничителем списаний. Если не удалось получить полную стоимость, подготовка продолжается, платное создание останавливается.

## Обновление

Один файл вручную: stage → preview → upload → import (дашборд обновляется сам) → report → сверка страницы дашборда с report.

Плановое получение из S3: серверный source.json содержит kind=s3_object и ключ внутри source/ согласованного приватного бакета. `sales_refresh_source` читает один полный объект, валидирует до записи и импортирует content-addressed снимок. Доступ к произвольным URL/чужим бакетам не принимается в tool arguments. Агент проверяет права чтения источника и записи incoming/ отдельно.

Worker `python -m cloudru_mcp.refresh --source` вызывается systemd timer на облачной VM. Агент устанавливает unit, согласованные timezone/частоту, source.json, bound.env и секреты. Установка Python/таймера пользователю не поручается. Шаблон — ежедневно 06:00 Europe/Moscow, это не согласие пользователя на такой график. Проверить один ручной вызов, затем один настоящий scheduled run с новым SHA. Для независимого автомата bearer MCP не нужен: worker имеет свой Cloud.ru/S3/CH доступ. Истечение MCP-токена останавливает управление через клиента, не обязано останавливать worker.

Не обещать мониторинг/уведомления, если не настроены и не проверены. Не добавлять рассылки от имени пользователя без поручения. Проверять свежесть источника отдельно от времени запуска.

## Разовая сдача и завершение

Ссылка на дашборд работает, пока работает VM MCP и IP пользователя входит в allowlist; смена IP требует обновить правило группы безопасности. Ссылка Managed BI (если используется) работает, пока доступны ресурсы и права пользователя. При необходимости неизменяемого файла/офлайн-результата проверить экспорт через API; текущий сервер не реализует export. Не обещать вечную ссылку после удаления БД или BI.

Приостановка расписания не прекращает оплату инфраструктуры. Удаление может уничтожить отчёт и снимки. Срок MCP-токена клиента ограничен (по умолчанию 7 дней); продление выполняет агент скриптом `rotate_token.py` на VM и перерегистрацией клиента, пользователя это не касается. Личный ключ доступа пользователя тоже имеет срок: перед его истечением попроси создать новый тем же шагом B и обнови секреты на сервере.

Текущий MCP намеренно не имеет destroy tool: агент описывает конкретные ресурсы и последствия, получает нужное разрешение и использует проверенный API-процесс оператора. Не обходить prevent_destroy автоматически. Указывать, если остановка расходов ещё не выполнена.

## Итог пользователю

«Готово: [Отчёт по продажам](проверенный URL).
Вход: [подтверждённый способ, без секретов].
Данные: [период и время последнего снимка]. Выручка [сумма], contribution [сумма].
Обновление: [разово / по вашему новому файлу / фактически проверенное расписание].
Стоимость: примерно [X] ₽ за 30 дней при [условиях], дата оценки [дата].
Чтобы обновить/изменить/остановить: напишите агенту [короткая команда].»

Не выдавать ссылку внутреннего private host как готовую для пользователя: проверить доступный пользовательский маршрут и вход. Если API-only проверка не может подтвердить интерактивный вход, попросить пользователя один раз открыть ссылку и сообщить, что отчёт доступен; агент браузер не использует.
