# Доступ: точные роли и границы подтверждения

Справочники сверены 28.10.2026. Это документированный профиль для подготовки пилота, **не доказанный минимальный набор для полного live apply**. Существование роли подтверждено источником; достаточность набора для конкретного provider/API проверяется отдельно. Не обещай, что роль автоматически подключает услугу, даёт квоту или заменяет авторизацию BI REST.

## Кому назначаются права

| Кто | Назначение |
|---|---|
| Человек в кабинете | Создаёт проект/сервисный аккаунт и выдаёт доступ; не передаёт программе свой пароль |
| `sales-report-agent` | Вызывает API для инфраструктуры отчёта; уровень «Проект», выбранный проект отчёта |
| Аккаунт, прикреплённый к кластеру Data Platform | Права для работы самого кластера; отдельная предпосылка, не автоматически тот же аккаунт |
| Пользователь, читающий отчёт | Доступ к нужному BI; не обязан получать права управления инфраструктурой |

Новый проект создаёт администратор организации. Управление аккаунтом уровня «Проект» доступно администратору соответствующего проекта; у администратора пользователей есть ограничения. Это требование к человеку, не указание выдать программе такую же роль. Источники: [проекты](https://cloud.ru/docs/administration/ug/topics/guides__projects), [редактирование прав](https://cloud.ru/docs/console_api/ug/topics/guides__service_accounts_edit-access).

## Основной профиль развёртывания

Все строки относятся только к согласованному проекту. Предпочитай отдельный пустой проект: сервисные роли могут давать изменение/удаление ресурсов всего сервиса в нём, хотя текущий MCP запрещает destroy. Это не абсолютный least privilege на отдельные ресурсы.

| Сервис в форме | Выбрать | Зачем в нашем шаблоне | Официальный источник |
|---|---|---|---|
| Виртуальные машины | `eiv.admin` | VM, диск, подсети, сетевые интерфейсы, SG и публичный IP; `eiv.compute_operator` не разрешает аренду IP | [VM](https://cloud.ru/docs/virtual-machines/ug/topics/security) |
| Evolution VPC | `vpc.admin` | Создать отдельную VPC | [VPC](https://cloud.ru/docs/evolution-vpc/ug/topics/security) |
| Evolution DNS | `cdns.admin` | Создать DNS-сервер и связать с VPC | [DNS](https://cloud.ru/docs/evolution-dns/ug/topics/security) |
| Managed ClickHouse | `dbaas.clickhouse.admin` | Создать и настроить кластер базы отчёта; DBA не даёт создание | [ClickHouse](https://cloud.ru/docs/clickhouse/ug/topics/security) |
| Data Platform | `dataplatform.admin` | Создать кластер платформы | [Data Platform](https://cloud.ru/docs/dataplatform/ug/topics/security) |
| Managed BI | `bi.admin` | Создать инстанс BI; `bi.user` не даёт создание инстанса | [BI](https://cloud.ru/docs/managed-bi/ug/topics/security) |
| Evolution Object Storage | `s3e.viewer`, `s3e.editor`, `s3e.viewer-acl`, `s3e.editor-acl` | Читать/загружать объекты, создать bucket, прочитать/настроить его приватность | [Object Storage](https://cloud.ru/docs/s3e/ug/topics/security__role) |

У S3 на этапе создания нового bucket права нужны на сервис выбранного проекта; область отдельного ещё не существующего bucket выбрать нельзя. После создания агент готовит отдельное сужение runtime-доступа, проверяя импорт и обновление; не меняет права молча. `s3e.admin` и «Администратор проекта» не являются удобной заменой четырём ролям: согласно документации такие права обходят Bucket Policy и ACL.

В S3 форма сервисных ролей использует блок **Evolution Object Storage**, а ограничения на существующие бакеты — блок **Роли на бакеты**. Для остальных сервисов точные заголовки вложенных элементов могут отличаться; агент сначала уточняет текущую форму, если пользователь не находит сервис. Не выдумывать единую кнопку «Добавить сервис» для всех версий кабинета.

## Условные предпосылки — решает агент, а не новичок

**Логи.** Если используется уже созданная log group, для просмотра есть `ls.user`; для записи — `logaas.writer`. Создание/изменение log group требует `ls.admin`. Выбирай только действия, реально нужные текущему аккаунту. Роль на запись для аккаунта кластера не подменяется ролью развёртывающего агента. [Источник](https://cloud.ru/docs/client-log/ug/topics/roles).

**Аккаунт кластера Data Platform.** Шаблон принимает `service_account_id`, но не создаёт и не наделяет его правами. Перед созданием кластера Cloud.ru требует настроить роли этого аккаунта. Агент открывает официальную инструкцию «Настроить роли», связанную со страницей [создания кластера](https://cloud.ru/docs/dataplatform/ug/topics/guides__create), и проверяет требования именно выбранных сервисов. На дату пересборки точный полный профиль этого аккаунта здесь не подтверждён. Если источник недоступен, отметь эту конкретную предпосылку как неподтверждённую и подготовь запрос администратору/поддержке; не говори пользователю выбирать роли наугад. Инструкцию формируй теми же карточками, когда точный профиль установлен. Не выдавать `dataplatform.admin` за все внутренние права кластера.

**Проектная роль.** В общем справочнике назначение роли в организации/проекте необязательно; сервисные роли можно назначать отдельно. Не добавляй «Пользователь проекта» как универсальное исправление: он наследует дополнительные права, и всё равно не заменяет admin-операции сервисов. Если конкретный discovery-запрос требует дополнительного права, выясни ресурс/действие и предложи точечное изменение или выполнение администратором. [Иерархия ролей](https://cloud.ru/docs/administration/ug/topics/concepts__roles).

**BI для человека.** Для просмотра дашборда предусмотрена `bi.viewer` на нужный инстанс. Права пользователя не равны правам программы и не доказывают поддержку API-авторизации текущим Managed BI. `bi.admin` не превращает IAM token в Superset JWT.

## Проверка после выдачи доступа

Агент проверяет через read-only API: выбранный проект, доступность сервисов/справочников, необходимые существующие предпосылки. Составляет краткий результат по каждому пункту: подтверждён / не хватает доступа / ещё не проверен. Успешное получение IAM-токена означает только аутентификацию. Ошибка API может быть связана с подключением сервиса, сетью, квотой или областью роли; не расширяй права до выяснения причины. Возможность записи окончательно подтверждается только разрешённым облачным выполнением после сметы.

Если нужен администратор, агент сам заполняет список конкретных ролей и причин из этого файла и отдаёт пользователю готовый текст для пересылки. Не оставляет фразу «назначьте необходимые права» и пустой шаблон ролей.
